Team inboxes save new push-delivery reports in Netlify Database when the existing authenticated notification sender reports to the site activity endpoint. Reports produce a delivery-log entry and inbox message in one atomic database statement. League-wide messages appear for every team; targeted messages appear only for their listed teams. The inbox does not depend on a browser having enabled push, and quiet hours affect push delivery rather than inbox history. Messages start accumulating after the inbox migration and endpoint are deployed.

The site uses public team selection rather than authenticated manager accounts. Inbox content is league notification content, not private correspondence. Read receipts are scoped to the existing browser device identifier plus selected team. They survive reloads and returning visits but do not synchronize between different devices. Switching teams preserves each team's independent unread state on that browser.

The team-name button opens the inbox, and switching teams remains available inside Inbox and My Team. Opening Inbox does not automatically clear unread messages. Mark read or Open related page marks a single message read; Mark all read uses the latest message ID seen by the client so newer arrivals stay unread. Requests recheck the audience before writing receipts, and late responses from a previously selected team are discarded.

Unread counts refresh while the page is visible, on reconnect, and after a service-worker push event. Inbox delivery reports currently omit deep links, so the endpoint chooses the related page from the notification title. Future reports may provide a same-site URL directly. Only the server-authenticated report path can create inbox messages; the browser API only reads messages and records its own read receipts.
